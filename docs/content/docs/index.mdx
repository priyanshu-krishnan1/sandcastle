## What is Sandcastle?

Sandcastle is a TypeScript library (published as `@ai-hero/sandcastle`) for running an AI coding agent against a git repository inside a sandbox, then bringing the resulting commits back to the host. It's used by writing a small script that calls its functions — there is no runtime config file.

At its core, `run()` does three things:

1. Creates a git worktree and starts a sandbox (a **sandbox provider**).
2. Invokes an AI CLI inside it, once per iteration (an **agent provider**), until the agent signals it's done or `maxIterations` is reached.
3. Merges or collects the commits the agent made, according to a **branch strategy**.

## Install

```bash
npm install --save-dev @ai-hero/sandcastle
```

The package ships one CLI command, `sandcastle init`, plus a library API (`run`, `interactive`, `createSandbox`, `createWorktree`, ...) that you import into your own script.

## Scaffold a project

```bash
npx @ai-hero/sandcastle init
```

This prompts for (or accepts as flags):

- `--template` — one of the templates listed below.
- `--sandbox` — `docker` or `podman`. This only picks which container-image file gets scaffolded (a `Dockerfile` or a `Containerfile`) — it does not select a runtime sandbox provider. See [Sandbox Providers](/docs/sandbox-providers).
- `--issue-tracker` — `github-issues`, `beads`, or `custom`. Substitutes the task-listing/viewing/closing commands into the generated prompt.
- `--model` — the mode/model passed to `bob`, the only built-in agent.

It creates a `.sandcastle/` directory containing:

| File | Purpose |
| --- | --- |
| `Dockerfile` or `Containerfile` | Image definition for the sandbox environment. |
| `.env.example` / `.env` | Environment variables (agent API key, issue-tracker token). See [Configuration](/docs/configuration). |
| `.gitignore` | Ignores `.env`, `logs/`, `worktrees/`. |
| `main.ts` or `main.mts` | The script you run — calls `run()` with your chosen agent and sandbox. |
| One or more `*-prompt.md` files | Prompt(s) sent to the agent, depending on the template. |

Templates (`--template`):

| Name | What it scaffolds |
| --- | --- |
| `blank` | A single prompt file and a `run()` call — write your own orchestration. |
| `simple-loop` | Picks issues one by one and closes them. |
| `sequential-reviewer` | Implements issues one by one, with a review step after each. |
| `parallel-planner` | Plans parallelizable issues, executes each on its own branch, merges. |
| `parallel-planner-with-review` | Same as above, with a review step per branch. |

The `blank` template's generated `main.mts` looks like this:

```typescript
import { run, bob, fyre } from "@ai-hero/sandcastle";

await run({
  agent: bob("default"),
  sandbox: fyre({ host: "your-host.example.com" }),
  promptFile: "./.sandcastle/prompt.md",
});
```

Fill in `.sandcastle/.env` (copy `.env.example`) with `BOB_API_KEY` and whatever your sandbox provider needs, point `fyre()` at a real host (or swap in another provider — see [Sandbox Providers](/docs/sandbox-providers)), then run it:

```bash
npx tsx .sandcastle/main.mts
```
